# Тихо

Спокойный todo-list на Astro и TypeScript. Тёплая бумажная палитра, заголовки с засечками, терракотовый акцент.

**Сайт:** https://tyrtyshnyy.github.io/todo-hermes-ai/

## Три пространства

- **На устройстве** — локальные задачи в `localStorage` (`tikho.tasks.v1`). Работает без аккаунта, данные не отправляются в Supabase.
- **Мои задачи** — личные и опубликованные задачи вошедшего пользователя, хранятся в Supabase PostgreSQL и доступны на других устройствах после входа.
- **Общая лента** — явно опубликованные задачи всех участников. Чтение доступно без входа; изменение — только автору.

Новая облачная задача **личная по умолчанию**. Для публикации нужно отметить «Опубликовать в общей ленте». Публичны название, имя автора, проект, срок, приоритет, статус и идентификатор автора; email не выводится. Имена выбирают пользователи, они не являются проверенными удостоверениями личности. Не публикуйте конфиденциальные сведения: прочитанное другими нельзя отозвать удалением или скрытием задачи.

Локальные задачи никогда не переносятся в облако автоматически. Для облака нужен интернет; при отказе записи приложение сохраняет прежнее состояние и сообщает об ошибке. Список обновляется кнопкой и при возврате фокуса; это не realtime. Загрузка страницами по 50 записей, поиск/фильтры применяются к загруженным задачам. Удаление облачной задачи безвозвратное, отмена удаления поддерживается только для локальных задач.

## Запуск и проверки

Node.js, поддерживаемый установленным Astro (проверено на Node 26):

```sh
npm ci
npm run dev
```

Адрес: http://127.0.0.1:4321. По умолчанию сервер слушает только localhost.

```sh
npm run check
npm test
npm run test:e2e -- --workers=1
npm run build
npm run preview
```

На машине с небольшим объёмом памяти используйте `NODE_OPTIONS=--max-old-space-size=384` для проверки и сборки. Для браузерных тестов нужен `npx playwright install chromium`; на минимальном Linux — библиотеки Chromium и fontconfig со шрифтами. Конфигурация использует проектную среду `.cache/`, если она есть; тестовый сервер работает на отдельном порту 4322.

Локальные HTTP-фикстуры облачного API в Playwright существуют **только в тестах**. Они проверяют поведение интерфейса, не заменяют проверку защиты БД. Реальные PostgreSQL-тесты RLS:

```sh
./supabase/tests/run.sh
```

Требуется Docker. Скрипт применяет настоящую миграцию в изолированной временной PostgreSQL, проверяет доступ для двух пользователей/гостя и удаляет контейнер. Схема `auth` имитирует контракт Supabase; это не проверка живой регистрации в проекте.

## Настройка Supabase

1. Создать проект и выполнить `supabase/migrations/001_todos.sql` в SQL Editor.
2. Authentication → Sign In / Providers → Email: провайдер включён, **Confirm email выключен**. Регистрация должна сразу возвращать сеанс без письма. Если подтверждение включено, приложение блокирует регистрацию до настройки и не вызывает отправку письма.
3. Authentication → URL Configuration:
   - Site URL: `https://tyrtyshnyy.github.io/todo-hermes-ai/`
   - Redirect URLs: тот же адрес; для локальной разработки при необходимости также `http://127.0.0.1:4321/`.
4. Открыть сайт → «Войти в аккаунт» → «Регистрация», придумать логин и пароль. Вход сразу после регистрации; почта не нужна. Логин: 3–32 латинские буквы/цифры/_, регистр игнорируется. Пароль: минимум 8 символов.

SDK Supabase требует email-образный идентификатор: логин однозначно отображается в `login@users.tikho.invalid` (зарезервированный недоставляемый домен). Это внутренний идентификатор, а не почтовый ящик. Не менять домен/алгоритм для существующих аккаунтов. Логин уникален благодаря уникальности идентификатора в Supabase Auth. Пароли проверяет Supabase, а не SQL-функции/наш клиент.

Нет восстановления пароля по почте: сохраните пароль в менеджере. Ранее созданные email-аккаунты и их данные не удаляются и не переименовываются автоматически; для их переноса нужен отдельный административный процесс.

По умолчанию `src/lib/supabase.ts` содержит URL и **публичный publishable key** выбранного проекта. Для другого проекта можно задать Astro-переменные `PUBLIC_SUPABASE_URL` и `PUBLIC_SUPABASE_PUBLISHABLE_KEY` при сборке. Эти параметры видны посетителям и не являются секретами. Никогда не используйте в браузере или репозитории `service_role`, `sb_secret_…`, пароль БД или административный токен.

Безопасность обеспечивает не ключ, а PostgreSQL RLS и минимальные GRANT: гость читает только публичное, вошедший пользователь меняет только своё. Миграция отзывает в том числе TRUNCATE. Изменения user_id на чужой запрещены. Таблица не даёт прямого доступа к `auth.users`.

Сеанс входа хранится SDK Supabase в браузере; выход удаляет локальный сеанс. На общем устройстве выходите из аккаунта. Восстановление пароля, социальный вход, модерация общей ленты и резервное копирование из интерфейса пока не реализованы. Настройки доставки/лимиты email и резервные копии зависят от проекта и тарифа Supabase.

## Возможности

Задачи: создание, редактирование, выполнение/возврат, удаление; три проекта, приоритеты, сроки, поиск, важные, сортировка. Представления: все активные, сегодня (включая просроченные), предстоящие, завершённые. Светлая/тёмная темы, мобильная боковая панель, клавиши N/Т и /. Примеры появляются только по явной кнопке в локальном режиме.

## Публикация

Код находится в `main`, сайт — в `gh-pages` (корень `/`).

```sh
GITHUB_ACTIONS=true npm run build
```

При этом базовый путь — `/todo-hermes-ai/`; локально — `/`. Опубликуйте содержимое `dist/` в `gh-pages` с `.nojekyll`. Автодеплой из `main` пока не включён: OAuth-токен не имеет права `workflow`. Шаблон `.github/pages-workflow.example.yml` можно перенести в `.github/workflows/pages.yml` после предоставления права и переключения источника Pages на GitHub Actions.

## Структура

- `src/pages/index.astro` — интерфейс, диалоги задач и входа.
- `src/styles/` — локальные и облачные стили.
- `src/scripts/app.ts` — интерфейс, сессия, локальные и облачные операции.
- `src/lib/state.ts`, `cloud.ts`, `supabase.ts` — модели/валидация/SDK.
- `supabase/migrations/` — таблица и политики доступа.
- `supabase/tests/` — реальные PostgreSQL-тесты прав.
- `tests/` — тесты модели и браузерные сценарии.
